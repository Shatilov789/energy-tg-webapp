# Роли и UI-карточки — Energy CRM

Справочник: что может каждая роль (по факту реализованного кода) + каталог всех карточек/экранов для дизайнера. Сверено с кодом на 2026-06-23 (backend endpoints + frontend pages), не с задумкой — если в коде фичи нет, она не упомянута.

## 1. Роли

Хранятся в `User.role` (enum `UserRole`: `WORKER` / `ADMIN`). Назначаются вручную через `POST /api/admin/users` или сидятся в `seed.py`. Нет самостоятельной регистрации с выбором роли — пользователь либо заведён админом, либо это dev-сид.

## 2. Матрица возможностей

| Действие | Worker | Admin |
|---|--:|---|
| Видеть свои объекты (созданные или к которым дали доступ) | ✅ | ✅ |
| Видеть **все** объекты всех воркеров | ❌ | ✅ (`GET /admin/objects`) |
| Создать объект (имя, комментарий, сценарий) | ✅ | ✅ |
| Заполнять шаги (ответы) в объекте, к которому есть доступ | ✅ | ✅ (доступ есть к любому объекту) |
| Редактировать **свой** ещё незаблокированный ответ | ✅ | ✅ |
| Редактировать **заблокированный** ответ | ❌ (403 — нужен unlock) | ✅ (роль обходит блокировку) |
| Разблокировать ответ (`is_locked → false`) | ❌ | ✅ |
| Дать доступ к объекту другому воркеру (share) | ✅ (если есть доступ сам) | ✅ |
| Тред-обсуждение шага — читать/писать, упомянуть коллегу | ✅ | ✅ |
| Ответить на сообщение в треде (`reply_to_id`) | ✅ | ✅ |
| Системные события в ленте (lock/unlock/admin_comment) | авто | авто |
| Список коллег для упоминания (`GET /users/`) | ✅ | ✅ |
| Оставить админ-комментарий к конкретному ответу (с уведомлением воркеру) | ❌ | ✅ (`POST /admin/answers/{id}/comment`) |
| Создать сценарий / добавить шаг в сценарий | ❌ | ✅ (`POST /scenarios/`, `POST /scenarios/{id}/steps`) |
| Создать пользователя по Telegram ID | ❌ | ✅ (`POST /admin/users`) |
| Активировать/деактивировать пользователя | ❌ | ✅ (`PATCH /admin/users/{id}/toggle-active`) |
| Список всех пользователей | ❌ | ✅ (`GET /admin/users`) |
| Получать уведомления (напоминание/unlock/комментарий/share/упоминание) | ✅ | ✅ |
| Вкладка "Админ" / дашборд в tab bar | ❌ (не отображается) | ✅ |

**Важный нюанс — блокировка ответа:** ответ создаётся с `is_locked=False` и остаётся редактируемым, пока админ не заблокирует его вручную. Заблокированный ответ воркер не может изменить, пока админ не нажмёт "Разблокировать".

**Известный пробел (не баг, просто не реализовано в UI):** текст админ-комментария (`AdminComment.comment_text`) сейчас нигде не показывается воркеру — приходит только generic-уведомление "Admin commented on step in '...'" без самого текста. Если нужно — отдельная задача.

## 3. Экраны (роуты)

| Страница | Роут | Кто видит | Назначение |
|---|---|---|---|
| HomePage | `/` | worker, admin | Список своих объектов (В работе / Завершённые / Новые), переход к заполнению |
| ObjectsPage | `/objects` | worker, admin | Форма создания нового объекта (имя, комментарий, выбор сценария) |
| StepPage | `/objects/:objectId/steps/:stepNumber` | worker, admin (если есть доступ к объекту) | Заполнение одного вопроса сценария + тред-обсуждение шага |
| HistoryPage | `/objects/:objectId/history` | worker, admin | Журнал отвеченных шагов по объекту + прогресс |
| NotificationsPage | `/notifications` | worker, admin | Лента уведомлений, типизированная по событию |
| AdminPage | `/admin` | **только admin** | Дашборд метрик + список всех объектов с возможностью unlock/comment |
| NotFoundPage | `*` | все | 404 |

## 4. Каталог карточек и компонентов (для дизайнера)

Цветовая база — `frontend/src/styles/global.css :root`:
`--bg: #0B0F17` (фон) · `--s1: #141926` (карточка) · `--s2/--s3` — более светлые поверхности (инпуты, треки прогресса) · `--acc: #E8A838` (единственный акцент, жёлто-янтарный — фирменный для "энергетики") · статусные цвета: `--ok` зелёный, `--err` красный, `--warn` оранжевый, `--purple` фиолетовый (только для "заблокировано"), `--acc2` синий (вторичные info-состояния).

### 4.1 Object card (HomePage)
Иконка сценария (цветной кружок 40×40, цвет зависит от типа сценария) + название объекта + бейдж "%" + строка `сценарий · создан ДД.ММ.ГГГГ · N дней` + тонкий progress-bar (4px) + опционально красная строка "Просрочено" с иконкой.
Варианты: **в работе** (жёлтый бейдж/бар), **завершён** (зелёный), **просрочен / не начат** (красный, 0%).

### 4.2 Scenario card / picker (ObjectsPage)
Кастомный dropdown (не нативный `<select>`): закрытое состояние — кружок-иконка + название + шеврон; открытая панель — список опций с иконкой+названием+чекмарком у выбранного. Под dropdown — превью выбранного сценария: крупная иконка 36×36, название, "N вопросов · описание", и до 5 чипов с текстом первых вопросов (+чип "+N" если больше).

### 4.3 Question card (StepPage) — минималистичный, без вложенных рамок
Заголовок вопроса (16px/700, без кружка-номера) → опциональный хинт мелким серым текстом → **единственная рамка во всём блоке** — textarea (фон чуть светлее страницы, радиус 16px, паддинг 16px, мин-высота 140px). Под textarea — один из трёх хвостов:
- **Сохранено** — зелёная плоская подпись с иконкой floppy-disk, без фона.
- **Заблокировано** — фиолетовая плоская подпись с иконкой lock, текст "только администратор может разблокировать".
- **Кнопка "Сохранить ответ"** — если есть несохранённые изменения (акцентная кнопка на всю ширину).

Состояния самой рамки textarea: default (нейтральная), `answered` (бордер чуть зелёный), `locked` (бордер чуть фиолетовый + textarea disabled/полупрозрачный).

### 4.4 Step header (StepPage, верх экрана)
Кнопка "назад" → маленькая цветная иконка сценария 32×32 → название объекта (bold) → подстрока "сценарий · в работе N дней" → одна тонкая progress-bar → текст "Шаг X из Y · Z%". Без точек-пипсов, без отдельного бейджа-плашки.

### 4.5 Discussion thread (StepPage, под карточкой вопроса)

Шаг состоит из двух **независимых** блоков: **Ответ** (основной бизнес-результат) и **Обсуждение** (вспомогательная коммуникация). Блоки разделены тонкой линией-разделителем.

#### Блок "Ответ"
Textarea с текстом ответа → статусный хвост (Сохранено / Заблокировано / кнопка "Сохранить"). Описание см. п. 4.3.

#### Блок "Обсуждение" (`.discuss-block`)
Заголовок "Обсуждение шага (N)" (uppercase, мелкий, серый) → лента записей → форма ввода.

**Лента записей** содержит два типа:

1. **Сообщение пользователя** — круглый аватар-инициалы + имя автора + опциональный бейдж `@Имя` (синий) + время + кнопка "Ответить" (иконка `corner-up-left`, появляется при hover/tap). Если сообщение является ответом на другое, над текстом показывается цитата (`discuss-quoted`): синяя левая полоса + имя оригинального автора + первые 2 строки текста.

2. **Системное событие** — итальянная строка во всю ширину: иконка + текст + время. Не удаляется, не редактируется.
   - 🔒 `lock` — "Администратор заблокировал ответ" (при PATCH /admin/answers/{id}/lock)
   - 🔓 `unlock` — "Администратор разблокировал ответ" (при PATCH /admin/answers/{id}/unlock)
   - 💬 `admin_comment` — "Администратор оставил комментарий" (при POST /admin/answers/{id}/comment)

**Форма ввода** — Telegram-style "таблетка": textarea + круглая кнопка-стрелка внутри. При нажатии "Ответить" на сообщении — над таблеткой появляется бар `discuss-reply-bar` с именем автора + цитатой + кнопкой отмены `×`; сообщение отправляется с `reply_to_id`.

### 4.6 Notification item (NotificationsPage)
Цветная иконка-кружок 36×36 (цвет/иконка зависят от типа) + заголовок + точка-индикатор непрочитанного + текст уведомления + время ("Сегодня в HH:MM" / "Вчера в HH:MM" / "N дн. назад" / дата) + опциональные кнопки действий ("Заполнить сейчас", "Посмотреть", "Прочитано").
5 типов с цветами: `reminder` красный, `step_unlocked` фиолетовый, `admin_comment` синий, `object_shared` зелёный, `step_comment` синий. Непрочитанное — рамка/подсветка карточки в цвет типа.

### 4.7 Admin dashboard metrics (AdminPage)
4 карточки 2×2: число крупное (28px/700, цвет акцента под метрику) + подпись сверху мелким caps + пояснение под числом. Метрики: "Выполнено %", "Объектов в работе", "Просрочено", "Завершено".

### 4.8 Admin object card (AdminPage)
Аватар-инициалы (цветной, ротация из 4 цветов) + имя создателя + "N/M вопр." + бейдж процента (или "Просрочен") + progress-bar + если есть заблокированный ответ — блок с вопросом в рамке, текстом ответа и двумя кнопками ("Разблокировать" фиолетовая, "Комментарий" синяя); если блокировки нет — просто кнопка "Комментарий".

### 4.9 Comment modal (AdminPage)
Полноэкранный оверлей, по центру — карточка: заголовок "Комментарий к ответу", текст вопроса серым, textarea, кнопки "Отмена"/"Отправить".

### 4.10 History card (HistoryPage)
Карточка прогресса (заголовок "Прогресс" + бейдж % + progress-bar + "N из M вопросов · Создан дата") + список отвеченных шагов как notif-item (зелёная иконка-чек + номер вопроса + текст + время ответа) + кнопка "Продолжить заполнение", если не всё отвечено.

### 4.11 Общие элементы
- **Tab bar** (низ экрана): Объекты / Создать / Оповещения (+ Админ, если роль admin) — текст+иконка, активная вкладка подсвечена акцентом, у "Оповещений" может быть красный бейдж-счётчик непрочитанных.
- **Badges** (`.bdg`): пилюли 11px с цветным фоном-тинтом — `ok` зелёный, `pend` жёлтый, `err` красный, `info` синий, `grey` серый, `lock` фиолетовый.
- **Primary button**: на всю ширину, акцентный фон, тёмный текст, радиус 14px.
- **FAB "Создать"**: круглая кнопка 44×44 с тенью в цвет акцента (HomePage, верхний правый угол).

## 5. Чего нет (чтобы не рисовать лишнее)
- Нет выбора роли при регистрации — роль назначает админ.
- Нет CRUD сценариев в UI (эндпоинты есть, экрана нет).
- Нет отображения текста админ-комментария воркеру (есть уведомление, нет текста в нотификации — отдельная задача).
- Нет question_type (choice/text) — все шаги текстовые (textarea).
- **Нет вложений в обсуждении** (фото/PDF/схемы) — модель и API не поддерживают файлы; отдельная задача (нужно file storage).
- **Нет системного события "Объект передан сотруднику"** в тред-обсуждении — share это объект-уровень, не шаг-уровень; реализация потребует запись события во все шаги объекта (дизайн-решение нужно).
