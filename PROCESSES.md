# PROCESSES.md — Бизнес-процессы Energy CRM

Описание всех процессов системы: кто делает, что происходит, какие права.
Файл для синхронизации понимания между разработкой и продуктом.

---

## Роли

| Роль | Описание |
|------|----------|
| **Admin** | Полные права: создаёт пользователей, управляет ответственными, блокирует/разблокирует ответы, комментирует от имени администрации |
| **Worker** | Сотрудник: создаёт объекты, заполняет комментарии к этапам, пишет в обсуждения |

---

## 1. Регистрация пользователя

**Кто:** Только Admin  
**Как:** Через AdminPage (или API) → вводит Telegram ID, имя, роль

**Шаги:**
1. Admin идёт в Telegram, просит сотрудника прислать свой `/myid` боту
2. Admin создаёт пользователя: `POST /admin/users` (telegram_id, first_name, last_name, role)
3. Сотрудник может войти в Web App — система узнаёт его по Telegram ID

**Важно:** Без регистрации Admin'ом войти нельзя (система отдаёт 401/403).

---

## 2. Создание объекта инспекции

**Кто:** Worker (или Admin)  
**Как:** ObjectsPage → выбрать сценарий → ввести название → нажать "Создать"

**Шаги:**
1. Выбирается сценарий (шаблон вопросов)
2. Вводится название объекта + необязательный комментарий
3. `POST /api/objects/` → создаётся Object, создатель автоматически добавляется как ответственный в `object_workers`
4. Объект появляется в HomePage в секции "В работе"

**Результат:** Object (status=in_progress), создатель = первый ответственный.

---

## 3. Управление ответственными за объект

**Кто:** Admin  
**Как:** AdminPage → карточка объекта → строка ответственных → кнопка "+" или "×"

**Добавить ответственного:**
1. Admin нажимает "+" у объекта
2. Выбирает сотрудника из списка (только Workers, кого ещё нет в списке)
3. `POST /admin/objects/{id}/workers/{user_id}` → добавляется строка в `object_workers`
4. Сотрудник сразу видит объект в своей HomePage и может заполнять комментарии

**Убрать ответственного:**
1. Admin нажимает "×" у тега сотрудника
2. `DELETE /admin/objects/{id}/workers/{user_id}` → строка удаляется
3. Сотрудник теряет доступ к объекту

**Права после добавления:**  
- Видит объект в своей HomePage  
- Может заполнять "Комментарий к этапу" на каждом шаге  
- Может писать в "Обсуждение шага"

**По умолчанию:** Создатель объекта автоматически ответственный.

---

## 4. Прохождение этапов (шагов) объекта

**Кто:** Ответственные за объект (Workers из object_workers) + Admin  
**Как:** HomePage → карточка объекта → "Продолжить" → StepPage

Каждый шаг содержит **два независимых блока:**

### 4.1 Комментарий к этапу (верхний блок)

**Кто пишет:** Только ответственные + Admin  
**Правила:**
- Первый раз: пустое поле → сотрудник пишет → "Сохранить" → создаётся запись
- Дополнение: существующий текст **readonly** (нельзя редактировать), ниже появляется поле "Дополнить комментарий..."
- При сохранении дополнения: `existing_text + "\n\n" + supplement` → одна строка в БД
- Admin может заблокировать ответ (`is_locked=True`) → поле дополнения исчезает
- Кнопка "Далее" активна только если комментарий сохранён (и нет несохранённого дополнения)

**API:**
- Первое сохранение: `POST /objects/{id}/steps/{step_id}/answer`
- Дополнение: `PUT /objects/{id}/steps/{step_id}/answer`
- Блокировка (Admin): `PATCH /admin/answers/{id}/lock`
- Разблокировка (Admin): `PATCH /admin/answers/{id}/unlock`

### 4.2 Обсуждение шага (нижний блок)

**Кто пишет:** Все у кого есть доступ к объекту (все ответственные + Admin)  
**Правила:**
- Тред-сообщения: можно цитировать (reply)
- Системные события отображаются курсивом: "Заблокировано", "Разблокировано", "Администратор оставил комментарий"
- Блокировка ответа автоматически создаёт системное событие в тред

**API:**
- `GET /objects/{id}/steps/{step_id}/comments` — загрузить тред
- `POST /objects/{id}/steps/{step_id}/comments` — отправить сообщение (reply_to_id: optional)

---

## 5. Навигация по шагам

**Кто:** Ответственные + Admin  
**Правила:**
- "Назад" (`←`) — всегда доступна если шаг > 1
- "Далее" (`→`) — доступна только когда комментарий сохранён (для ответственных)
- Admin листает без ограничений
- Последний шаг → кнопка "Отправить отчёт" → переход на главную

---

## 6. Администрирование ответов

**Кто:** Admin  
**Как:** AdminPage → карточка объекта → список ответов

**Действия:**
- **Заблокировать** (`PATCH /admin/answers/{id}/lock`) — делает ответ readonly для Worker, создаёт системное событие "lock", уведомление сотруднику
- **Разблокировать** (`PATCH /admin/answers/{id}/unlock`) — Worker снова может дополнять, системное событие "unlock", уведомление
- **Комментарий** (`POST /admin/answers/{id}/comment`) — Admin пишет комментарий к конкретному ответу, Worker видит его под полем ответа, приходит уведомление

---

## 7. Уведомления

**Получает:** Worker  
**Когда:**

| Событие | Уведомление |
|---------|-------------|
| Admin заблокировал ответ | "Шаг заблокирован" |
| Admin разблокировал ответ | "Шаг разблокирован" |
| Admin оставил комментарий к ответу | "Комментарий администратора" |
| Упоминание в обсуждении (`@Имя`) | "Упоминание в обсуждении" |
| Напоминание (2 дня без активности) | "Напоминание" (APScheduler) |

---

## 8. Доступ к просмотру объекта

| Кто | Видит объект | Пишет комментарий к этапу | Пишет в обсуждение |
|-----|--------------|--------------------------|---------------------|
| Admin | Все объекты | Да | Да |
| Ответственный (ObjectWorker) | Свои объекты | Да | Да |
| Остальные Workers | Нет | Нет | Нет |

---

## 9. Статусы объекта

| Статус | Условие |
|--------|---------|
| `in_progress` | Не все шаги заполнены |
| `completed` | Все шаги заполнены (авто или вручную) |

*Примечание: автоматический перевод в completed не реализован — нужно добавить.*
